# Internationalisation (FR / EN)

L'interface existe en français (défaut) et en anglais. Les catalogues sont dans le crate
`crates/pf-i18n` ; l'application n'écrit plus aucun texte d'interface en dur.

## Utilisation

- Menu **Affichage › Langue › Français / English** : effet immédiat sur toute l'interface
  (menus, barre d'outils, panneaux, palette, inspecteur, dialogues, aide F1, barre d'état,
  étiquettes du canevas). Le choix est mémorisé.
- Option de lancement `--lang fr|en` : impose la langue pour la session sans modifier le
  réglage enregistré (utile aux captures : `patternforge --demo --lang en --screenshot x.png`).
- Séparateur décimal d'affichage : virgule en français (`120,5 mm`), point en anglais
  (`120.5 mm`). La saisie accepte toujours les deux (`120,5` et `120.5`).

## Persistance

Fichier `settings.json`, hors projet : `{"language":"fr"}`.

| Plateforme | Dossier |
|---|---|
| Windows | `%APPDATA%\PatternForge\` |
| Autres | `$XDG_CONFIG_HOME/patternforge`, sinon `$HOME/.config/patternforge` |

Fichier absent, illisible, corrompu ou valeur inconnue : français, sans écriture. Les autres
clés d'un fichier valide sont conservées à l'enregistrement ; l'écriture passe par un fichier
temporaire puis un renommage. Les fonctions (`load_language`, `save_language`) prennent le
chemin en paramètre : les tests utilisent un dossier temporaire et n'écrivent jamais dans le
dossier utilisateur (`App::with_context` n'a pas de chemin de réglages ; seul `App::new`,
le lancement réel, en a un).

## Conception

- `pf_i18n::Lang { Fr, En }`, `set_lang` / `lang` : langue **par fil d'exécution**
  (`thread_local!`), car chaque test tourne dans son propre fil.
- `tr(clé)` et `tr_args(clé, &[("nom", valeur)])` (remplace `{nom}`). Résolution : langue
  courante, puis français, puis la clé elle-même. Jamais de panique.
- Catalogues : `crates/pf-i18n/src/fr.rs` et `en.rs` (tableaux `&[(&str, &str)]`).
- Clés stables nommées par zone : `menu.file.new`, `tool.segment.label`, `status.point.placed`,
  `inspector.sheet.title`, `palette.length`, `help.limits`…
- Hors catalogue : les raccourcis neutres (`Ctrl+S`, `V`, `F2`, `Tab`), les unités (mm, °, cm²),
  le nom `PatternForge`, les noms de langues (`Français`, `English`). Les **noms de touches**
  localisés (Entrée/Enter, Échap/Esc, Suppr/Del, Maj/Shift, Origine/Home) sont, eux, dans le
  catalogue (`key.*`).
- `pf_core::input::set_decimal_separator(char)` (aussi `thread_local!`, défaut `,`) règle le
  séparateur de `format_number` / `format_mm` / `format_deg`. L'interface le recale à chaque
  image d'après la langue courante.
- `apps/pf-desktop/src/text.rs` : noms de tracés (« Segment AB » / « Courbe AC » avec préfixe
  traduit), libellés de rôles, et `core_error` (voir ci-dessous).

## Ajouter ou modifier un texte

1. Ajouter la clé **dans `fr.rs` et `en.rs`** (mêmes `{placeholders}`).
2. L'appeler par un littéral : `tr("zone.nom")` ou `tr_args("zone.nom", &[...])`. Écrire les
   clés en littéral directement dans l'appel (pas de clé construite avec `format!`), sinon le
   contrôle automatique ne les voit pas.
3. Lancer `cargo test -p pf-i18n -p pf-desktop`.

Ajouter une langue : nouveau fichier de catalogue, variante de `Lang`, entrée dans
`Lang::ALL` / `code` / `from_code` / `catalog` ; les tests de cohérence s'appliquent
automatiquement.

## Contrôles automatiques

- `pf-i18n` : mêmes clés en FR et EN, mêmes `{placeholders}`, aucune valeur vide, clés
  uniques et bien formées, `tr_args`, replis (FR puis clé), persistance (absent, corrompu,
  valeur inconnue, aller-retour, dossier créé), chemins par plateforme.
- `pf-desktop` (`i18n_tests.rs`) : toutes les clés passées à `tr("…")` / `tr_args("…"` dans
  `apps/pf-desktop/src/*.rs` (hors tests) existent dans les deux catalogues ; les clés de
  catalogue jamais utilisées sont signalées sur stderr sans faire échouer ; un échantillon
  de chaînes françaises connues et tout littéral contenant une lettre accentuée sont refusés
  dans le code hors catalogue ; bascule FR → EN → FR sur la vraie boucle egui ; parcours de
  l'interface en anglais (les 11 outils, y compris en cours de geste, palette, inspecteur de
  points / tracés / crans / paires / feuille, fenêtre Transformer dans ses trois modes,
  dialogues, aide).
- `pf-core` (`tests/decimal_separator.rs`) : séparateur `.` en affichage, isolé par fil.

## Limites assumées de cette itération

- **Messages d'erreur du cœur en français.** Les `Display` de `CoreError`, `GeometryError` et
  `ExportError`, ainsi que les messages de `pf_core::input` (« valeur vide », « n'est pas un
  nombre ») et les notes de `Outcome` (point devenu libre après suppression d'un tracé),
  restent en français. L'interface les affiche précédés d'un préfixe traduit
  (`Erreur : …` / `Error: …`, `Note : …` / `Note: …`, `Longueur : …` / `Length: …`).
  Ils ne sont pas réécrits ici.
- **Contenu des projets.** Les noms saisis par l'utilisateur ne sont jamais traduits. Le nom de
  la première feuille d'un nouveau projet (« Feuille 1 ») est créé par `pf-core`
  (`Project::new`) et reste donc en français ; le nom du projet (« Nouveau projet » /
  « New project ») et les feuilles ajoutées ensuite (« Feuille n » / « Sheet n ») sont créés
  dans la langue courante, puis figés. Les libellés de points (A, B, P…) viennent du modèle.
- **Exports.** Les mentions écrites dans les fichiers PDF et SVG (par exemple « tracé de
  construction ») restent en français : c'est le travail de `pf-export`. L'interface le
  précise en anglais dans l'inspecteur d'impression.
- **Message de console.** `capture impossible : …` (écrit sur stderr si l'enregistrement d'une
  capture échoue) n'est pas un texte d'interface et reste en français.
- **Polices.** egui n'embarque pas toutes les polices : seuls le français et l'anglais (latin)
  sont garantis. Une langue à alphabet non latin demandera des polices supplémentaires.
- Le séparateur décimal des champs numériques natifs egui (`DragValue` des positions et
  distances de l'inspecteur) est celui d'egui (point) quelle que soit la langue.
